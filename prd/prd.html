一句话定位

AI 基于用户上传的「简历 + 知识集」进行多轮模拟面试：扮演面试官逐题深挖、逐轮反馈，面试结束生成结构化评估报告，并支持历史会话与断点续聊。

需求背景

[PM judgment] 求职者面试准备存在三个痛点：

  • 缺乏真实反馈：自我练习无法判断回答质量，也不知道面试官会往哪个方向追问。
  • 练习与个人情况脱节：通用面试题与自己的简历项目、目标岗位 JD 对不上，练不到点子上。
  • 复盘成本高：面试后缺少结构化评估，改进方向不明确。

[Research-backed] 大模型 + RAG 技术栈已成熟（DeepSeek、bge 中文向量、Qdrant、Elasticsearch），可用较低成本构建「简历/知识库驱动的个性化面试官」，这是本产品的技术窗口。

产品目标

  • 让用户获得与真实面试相近的练习体验：问题个性化（基于简历 + 知识库）、反馈即时（逐轮追问与点评）、复盘结构化（评分报告）。
  • 量化基线（上线后抽测）：面试完成率 ≥ 80%；用户对「问题与自身情况相关性」的评分 ≥ 4/5。

目标用户与核心场景

  • 场景 1 · 针对性模拟：用户上传简历与目标岗位 JD / 技术文档 → 新建「技术面」→ AI 围绕简历项目深挖，结合 JD 出题，回答后自动追问。
  • 场景 2 · 随时续聊：面试中途离开，稍后回到会话列表继续上一次面试，上下文不丢。
  • 场景 3 · 复盘改进：面试结束查看评分报告与关键问题回顾，事实性陈述附信源校验（web_verify）。

F1 会话管理 P0

页面布局

「面试对话」模块由三块构成：左侧导航与最近会话列表；主区为会话卡片列表（标题、类型、状态、进度、操作按钮）；右上「新建面试」按钮弹出配置弹窗（面试场景、面试类型、岗位方向、关联知识库、关联简历、题目数量）。

业务逻辑

用户进入「面试对话」页，看到按时间倒序的会话列表。点击「新建面试」弹出配置窗：选择面试场景（实习 / 全职，决定整体难度与追问深度）、面试类型（技术面：围绕技术方案与原理深挖；行为面：STAR 情景问题；综合：两者混合），填写岗位方向（P0 起必填，用于生成通用题目语境），可选关联知识库（P1 起，出题与回答可引用知识）、关联简历（P2 起，出题优先围绕简历项目）。确认后后端创建会话并分配 thread_id，前端跳转至对话页。每个会话卡片展示标题（岗位 + 类型）、面试场景徽标、消息数、当前进度（第 N/总数题）与状态（进行中 / 已完成）；点击卡片或「继续面试」进入对话页并恢复上下文（断点续聊）；「查看报告」跳转报告页。删除会话需二次确认。

字段规则

字段类型必填范围 / 约束默认
面试场景单选是实习 / 全职（实习难度偏低，不深挖底层原理）全职
面试类型单选是技术面 / 行为面 / 综合技术面
岗位方向文本是≤ 50 字无
关联知识库下拉否已就绪文档可选 [P1]不使用
关联简历下拉否解析成功的简历 [P2]未上传
题目数量数字是5–30 整数10

状态流转

当前状态允许操作下一状态触发条件
进行中继续 / 删除已完成 / 已删除题目答完或用户主动结束；删除需确认
已完成查看报告 / 删除—报告生成后

边界与异常

  • 未选择任何知识库时，出题退化为通用题库（fallback 路径，见规则 R2）。
  • 删除会话为不可恢复操作，弹窗二次确认。
  • 无历史会话时展示空态引导：「点击右上角新建你的第一场模拟面试」。

F2 面试对话 P0P1P2

页面布局

对话页自上而下：顶部栏（返回、会话标题、类型与状态徽标、题目进度条、结束面试按钮）；中部对话流（AI 气泡与用户气泡交错，AI 气泡下方可带知识库引用标签）；底部输入区（多行输入框 + 提示一下 / 跳过此题 / 发送）；右侧信息栏（本轮评估要点、会话信息）。

业务逻辑

进入会话后，AI 以面试官角色按题库顺序出题（P0 为通用题库；P1 出题时先对用户输入做检索，命中知识则基于知识出题并附引用标签，可点击定位到原文段落；P2 优先从简历项目深挖）。面试场景决定出题与追问深度：实习场景以基础概念、八股要点与项目介绍为主，不追求复杂场景题，不深挖知识底层原理；全职场景为常规面试深度，可涉及场景设计与原理追问。用户提交回答后，AI 输出点评并视情况追问 1–2 轮，然后进入下一题；回答与追问均通过 SSE 逐 token 流式渲染，发送后输入框清空并显示「正在输入」指示。用户可点「提示一下」获得思路要点（每题 1 次，不计分），「跳过此题」进入下一题并在报告中标记「未作答」。全部题目答完或用户点击「结束面试」时，进入报告生成流程（F5）。进度条随当前题号更新。右侧「本轮评估要点」由评估节点实时生成，作为对话中的即时反馈。

字段规则

字段类型约束
回答内容文本单次 ≤ 5000 字；Enter 发送，Shift+Enter 换行
提示次数计数每题 ≤ 1 次
追问轮次计数每题追问 1–2 轮后换题

交互状态

用户操作系统响应
发送回答清空输入框 → 追加用户气泡 → 显示 AI 输入中 → 流式输出回复
提示一下追加系统气泡「提示要点」；已用完提示次数时按钮置灰
跳过此题追加系统气泡「已跳过，进入下一题」，进度 +1
结束面试二次确认 → 进入报告生成（F5）

边界与异常

  • LLM 调用超时 / 限流：重试 1 次；仍失败按 fallback 文案回复并记录日志（R2）。
  • 检索服务（Qdrant / ES）单点不可用时降级为单路召回并告警（R6）。
  • 用户 30 分钟无操作：会话标记为「已暂停」，下次进入自动续聊。
  • P0 阶段无知识库时，出题完全走通用题库，不允许出现「检索失败」类报错。

F3 简历管理 P2

页面布局

「简历管理」页由上传区与解析结果区组成：顶部拖拽上传区（支持 PDF / Word，≤ 20MB）；下方为解析结果卡片（基本信息、技能标签、项目经历、教育背景、题库生成按钮），以及失败案例卡片（失败原因 + 重新上传）。

业务逻辑

用户上传简历文件后，系统进入解析流水线：文件校验（格式 / 大小）→ Docling 解析 → 结构化抽取（基本信息、教育经历、工作经历、项目经历、技能、期望岗位）→ 状态流转（上传中 → 解析中 → 成功 / 失败）。解析成功后自动构建个性化面试题库（覆盖自我介绍、项目深挖、技能考察、行为面，≥ 10 题），用户可在新建会话时关联该简历，面试出题即引用题库并按项目逐条深挖。解析失败展示失败原因（如「扫描件无文字层」）并支持重新上传。成功与失败状态在列表中并存展示，便于用户区分处理。

字段规则

字段约束
文件格式PDF（含文字层）/ Word（docx）
文件大小≤ 20MB
题库数量≥ 10 题 / 份简历

状态流转

状态操作触发条件
上传中 → 解析中—文件校验通过
解析中 → 已就绪生成题库 / 关联会话结构化抽取完成
解析中 → 失败重新上传 / 删除解析异常或无可提取文本

边界与异常

  • 扫描件（无文字层）给出明确失败原因与换源建议，不静默失败。
  • 解析为异步任务，期间允许用户离开页面，完成状态下次进入可见。

F4 知识库管理 P1

页面布局

「知识库」页由上传区、文档列表（文件名、格式、切块数、状态徽标、查看 / 删除）、检索设置卡（语义 / 关键词权重滑块、Top-K）组成。

业务逻辑

用户上传知识文档（PDF / Word / Markdown，≤ 50MB）后进入入库流水线：Docling 解析 → 父子切块（父块约一个段落 ≤ 800 字，子块 2–3 句 ≤ 200 字）→ 子块向量化写入 Qdrant（bge-large-zh-v1.5，1024 维；亦可选外部 API），父块全文写入 Elasticsearch（ik_max_word 分词）→ 状态流转（解析中 → 切块中 → 向量化中 → 已就绪 / 失败）。文档列表展示切块数供用户感知规模。检索设置支持调整双路召回权重（语义 / 关键词）与 Top-K（默认 5）；检索命中子块时返回其父块作为 LLM 上下文。删除文档时级联清理 Qdrant 向量与 ES 索引，删除后检索不再命中。文档状态异步更新，入库中状态允许用户离开页面。Embedding 模型可配置（本地 bge-large-zh-v1.5 / 外部 API）：知识库创建时绑定所用模型（model_id + 维度），切换模型需对库内文档重建索引；选用外部 API 时页面展示「内容将发送至第三方」提示。

字段规则

字段约束
文件格式PDF / DOCX / MD / TXT
文件大小≤ 50MB / 文件；超过 500 页提示拆分
切块参数父块 ≤ 800 字；子块 ≤ 200 字（2–3 句）
召回参数Top-K 默认 5；权重可调，范围 0–1 步进 0.05
Embedding 模型本地 bge-large-zh-v1.5（默认，1024 维）/ 外部 API；库绑定 model_id，切换需重建索引

状态流转

状态操作触发条件
解析中 → 切块中 → 向量化中取消流水线各步骤完成
向量化中 → 已就绪查看 / 删除 / 检索使用Qdrant 与 ES 均写入完成
任一环节 → 失败重试 / 删除解析异常、切块失败、向量服务不可用

边界与异常

  • Qdrant 或 ES 单点不可用时，入库任务标记失败并保留原文件，恢复后可重试；检索侧降级为单路（R6）。
  • 删除文档为级联操作，成功后提示「已删除 N 个块」。
  • 切换 Embedding 模型时，库内已向量化文档需重建索引；重建完成前检索被拦截并提示。

F5 面试报告 P0P2

页面布局

报告页自上而下：标题与状态徽标；总分环形图 + 四个维度条形（技术深度、沟通表达、逻辑思维、项目经验）；优点 / 待改进双栏；关键问题回顾表（问题、参考要点、校验状态）；底部「再来一场 / 导出报告」操作。

业务逻辑

面试结束（全部题目答完或用户主动结束）后，评估节点汇总全程回答生成报告：总分（100 分制）与四维度评分、优点 / 待改进条目、关键问题回顾（每题参考要点）。P2 起，对含事实性陈述（数字、日期、定义、外部事件）的回答触发 web_verify 校验（R4）：校验结果在回顾表中标记「已核验 / 存疑 / 无法确认」，存疑项附信源链接（source=web[url]）。生成过程展示「报告生成中」加载态，完成后可查看。「再来一场」复用本次会话的配置（类型、岗位、知识库、简历、题目数量）直接新建会话，「导出报告」下载为 Markdown。

状态流转

状态操作触发条件
生成中等待结束面试后异步生成
已生成查看 / 导出 / 再来一场评分与回顾完成
生成失败重试评估节点异常

边界与异常

  • 生成失败不阻塞会话数据，可重试；重试前保留已完成的会话消息。
  • web_verify 为可选节点：网络不可用或搜索配额耗尽时，校验标记为「无法确认」，不影响报告主体生成。

F6 环境配置 P0

页面布局

「环境配置」页由若干配置卡片组成：LLM API Key（DeepSeek，必填，密码框 + 显示切换）；Embedding 服务（本地 bge / 外部 API 二选一，[P1] 启用；选用外部 API 展示「内容发送至第三方」提示）；联网搜索 API Key（Tavily / SerpAPI，[P2] 启用）；底部「保存配置」按钮与测试连接入口。

业务逻辑

用户首次进入应用时若无可用 Key，弹出引导前往环境配置页。配置项保存在后端本地运行时配置（.env / 运行时内存），前端不落盘；保存时后端校验格式（LLM Key 以 sk- 开头），可发起一次测试调用验证连通性。Key 变更生效策略：新会话使用新 Key；进行中的会话沿用会话开始时的 Key，避免流式中断。未配置 LLM Key 时，新建 / 继续会话被拦截并提示「请先配置 LLM API Key」，不产生半截对话。

字段规则

字段必填范围 / 约束生效时机
LLM API Key是DeepSeek Key，sk- 开头保存后新会话生效
Embedding 配置否本地 bge-large-zh-v1.5（默认）/ 外部 API（Base URL + Key）；切换触发知识库重建 [P1]保存后入库 / 检索生效；切换后需重建索引 [P1]
联网搜索 Key否Tavily / SerpAPI [P2]保存后 web_verify 生效 [P2]

边界与异常

  • Key 仅存后端本地运行时配置（gitignore），不入版本库、不写入前端 localStorage 明文。
  • 测试连接失败给出明确错误（无效 Key / 网络不通），不进入保存流程。
  • 进行中会话不因 Key 变更而中断；旧 Key 失效时该会话按 R6 降级提示，不报堆栈。
  • 选用外部 API Embedding 时，知识库内容将发送至第三方，页面展示外发提示；本地 bge 模型数据不出本机。

业务规则

需求详情未展开的跨模块规则、降级策略与边界约定。

R1 · 面试对话规则

  • 出题顺序：主问题 →（用户回答 → AI 追问 1–2 轮）→ 下一题；AI 可基于回答内容自主决定追问是否必要。
  • 面试场景：实习 / 全职固定于会话创建时；实习场景出题以基础概念、八股要点与项目介绍为主，不深挖底层原理；全职场景可涉及场景设计与原理追问；两场景追问轮次相同（1–2 轮），难度差异靠题目本身。
  • 提示：每题最多 1 次提示；提示由 LLM 生成思路要点，不计入评分。
  • 跳过：跳过题目在报告中标记「未作答」，不计分但不中断流程。
  • 结束：达到题目总数自动结束；用户可中途主动结束；结束即触发报告生成。
  • 会话隔离：一个会话对应一个 thread_id；题库索引、追问计数、评估草稿均保存在会话状态中，互不串扰。

R2 · 检索与四级降级（P1）

级别触发条件回答行为
normalTop-K 中强相关块（相关性 ≥ 阈值 0.6 [待定]）可支撑回答基于知识回答，回答附来源引用（文档名 + 段落号）
weak存在部分相关信息但不足以完整作答弱引用回答，明确告知「知识库中信息有限」，给出可参考方向
fallback无召回或无相关块使用通用面试题库回答（不附引用），问题不报错、不展示失败
decline连续 fallback ≥ 2 次，或用户问题明显超出面试范围建议补充知识库 / 引导换题，并提示可跳题

R3 · 知识入库规则（P1）

  • 格式与大小：PDF / DOCX / MD / TXT；≤ 50MB / 文件。
  • 切块：父块 ≈ 段落（≤ 800 字）；子块 = 2–3 句（≤ 200 字）；父子映射保留。
  • 存储：子块向量入 Qdrant（bge-large-zh-v1.5）；父块全文入 ES（ik_max_word 分词）。
  • 双路召回：ES BM25 与 Qdrant 语义按权重合并 → 去重 → Top-K 重排（默认 K=5）。
  • 上下文：命中子块时返回对应父块作为 LLM 上下文，保证段落完整性。

R4 · web_verify 事实校验（P2，可选节点）

环节规则
触发用户回答含可校验事实（数字、日期、定义、外部事件）时，由 LLM 判定是否触发校验 [待确认]
搜索Tavily / SerpAPI 联网搜索，query 为回答中的事实断言
信源过滤优先官方文档 / 权威站点；过滤低质与无关结果
比对搜索结果与用户断言做相关 / 冲突判定
输出标记「已核验 / 存疑 / 无法确认」，存疑项附 source=web[url]

R5 · 数据与存储规则

数据存储说明
会话 / 状态LangGraph checkpointerP0 MemorySaver（内存）；P2 起 SqliteSaver（interview.db），重启可恢复
简历文件系统 / SQLite blob解析结果（结构化字段 + 题库）随简历存储
知识集Qdrant + ES子块向量 + 父块全文，级联删除
配置omegaconf + .env敏感项（API Key）不入库、不入版本控制

R6 · 边界与异常

  • LLM 异常：超时 / 限流重试 1 次，仍失败 → fallback 文案，loguru 记录 warning。
  • 检索服务异常：Qdrant / ES 单点故障 → 单路降级 + 告警日志；不向用户暴露内部错误。
  • 入库失败：状态标记失败 + 原因，保留原文件，支持重试。
  • 输入校验：消息长度、文件类型 / 大小、题目数量范围在服务端二次校验。
  • 并发：同一会话同一时刻仅一个进行中的流式回复；新建请求返回「上一回复生成中」提示。

验收标准

按阶段组织。验收方式分「自动化」（脚本 / 接口测试可判定）与「人工抽检」（需人工体验或抽样评审）。每阶段验收全部通过后进入下一阶段；验收结论与通过清单记入 CHANGELOG。

ℹ️
验收基线环境：Chrome / Edge 最新稳定版；单机部署（本地服务）；DeepSeek API 正常配额。
