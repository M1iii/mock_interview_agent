# 计算机网络面试知识

## 三次握手与四次挥手

TCP 三次握手是客户端 SYN、服务端 SYN+ACK、客户端 ACK 的交互过程，用于确认双方收发能力并同步序列号。四次挥手因 TCP 全双工需双方各自关闭，客户端 FIN、服务端 ACK、服务端 FIN、客户端 ACK。

## TIME_WAIT

TIME_WAIT 是主动关闭方收到对端 FIN 后进入的状态，持续 2MSL 时长，作用是保证最后一个 ACK 可达并让旧连接报文在网络中自然消亡。大量 TIME_WAIT 可通过开启 tcp_tw_reuse 或长连接复用缓解。

## 滑动窗口与流量控制

TCP 滑动窗口机制让发送方无需等待每个确认即可连续发送窗口内的数据，接收方通过通告窗口大小控制发送速率实现流量控制。窗口大小受接收缓冲区剩余空间约束，避免接收方被数据淹没。

## 拥塞控制

TCP 拥塞控制包含慢启动、拥塞避免、快重传和快恢复四个算法，慢启动指数增长拥塞窗口到 ssthresh 后进入拥塞避免线性增长。出现丢包超时重新慢启动，收到三个重复 ACK 触发快重传与快恢复。

## HTTP 与 HTTPS

HTTP 是明文传输的应用层协议，HTTPS 在 HTTP 与 TCP 之间加入 TLS 层实现加密传输、身份认证和数据完整性校验。HTTPS 握手增加往返时间并消耗 CPU 加解密资源，可通过会话复用降低开销。

## TLS 握手

TLS 握手先协商加密套件与 TLS 版本，服务端发送证书，客户端验证证书并生成预主密钥，用服务端公钥加密传回，双方基于预主密钥派生会话密钥后切换加密通信。TLS 1.3 握手精简为一次往返。

## HTTP/1.1 与 HTTP/2

HTTP/1.1 存在队头阻塞和请求响应串行问题，HTTP/2 引入二进制分帧、多路复用、头部压缩 HPACK 和服务端推送。HTTP/2 多路复用解决应用层队头阻塞，但 TCP 层队头阻塞依然存在。

## 输入 URL 到渲染

输入 URL 到页面渲染经历 DNS 解析、TCP 连接、HTTP 请求与响应、浏览器解析 HTML 构建 DOM 树等阶段。随后 CSS 构建样式树、JS 执行合成渲染树，最终布局绘制呈现页面，DNS 与 TCP 可通过缓存和连接复用加速。

## DNS 解析

DNS 解析按浏览器缓存、系统 hosts 文件、本地 DNS 服务器、根域名服务器、顶级域名服务器、权威服务器的顺序逐级查询，最终返回域名对应的 IP 地址。A 记录解析 IPv4，AAAA 记录解析 IPv6。

## WebSocket 与轮询

WebSocket 通过 HTTP 升级握手建立全双工长连接，服务端可主动推送消息，相比轮询和长轮询显著降低延迟与重复请求开销。轮询是客户端定时请求，长轮询是服务端挂起请求直到有新数据再返回。
