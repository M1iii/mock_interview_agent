# MySQL 面试知识

## B+ 树索引

MySQL InnoDB 索引底层使用 B+ 树结构，非叶子节点只存索引键值，叶子节点存全部数据并通过双向链表相连，天然适合范围查询和排序。B+ 树高度一般为 2 到 4 层，查询稳定高效。

## 聚簇与非聚簇索引

聚簇索引的叶子节点直接存放整行数据，InnoDB 的主键索引就是聚簇索引，非聚簇索引（二级索引）叶子节点存放主键值，回表时再通过主键查询完整数据。InnoDB 表必有聚簇索引，无主键时按首个唯一索引生成，都没有则由隐藏 rowid 充当。

## 索引失效场景

索引失效的典型场景包括对索引列使用函数或表达式、隐式类型转换、前导模糊查询 like '%xx'、联合索引不满足最左前缀、or 连接非索引列等。优化器也可能因回表成本放弃索引而走全表扫描。

## 事务 ACID

事务具有原子性、一致性、隔离性和持久性四个特性，原子性由 undo log 回滚保证，持久性由 redo log 保证。隔离性由锁和 MVCC 机制保证，一致性是前三者共同作用的结果。

## 隔离级别

MySQL InnoDB 提供读未提交、读已提交、可重复读和串行化四种隔离级别，默认是可重复读。读已提交与可重复读均通过 MVCC 实现，可重复读配合间隙锁解决了幻读问题。

## 锁与死锁

InnoDB 锁分为共享锁和排他锁，按粒度分为行锁和表锁，行锁通过索引实现，未命中索引时退化为表锁。行锁又分记录锁、间隙锁和临键锁，死锁指两个事务互相持有对方所需资源，InnoDB 通过死锁检测回滚代价较小的事务解决。

## EXPLAIN 执行计划

EXPLAIN 用于查看 SQL 执行计划，重点字段包括 type 访问类型、key 实际使用的索引、rows 预估扫描行数和 Extra 附加信息。type 从好到差依次为 system、const、eq_ref、ref、range、index、ALL，全表扫描应避免。

## 慢查询优化

慢查询优化先通过慢查询日志定位慢 SQL，再用 EXPLAIN 分析执行计划，常见手段包括建立合适索引、避免 SELECT *、优化 JOIN 与子查询、拆分大事务。目标是把 type 提升到 ref 以上并减少扫描行数。

## 分库分表

分库分表解决单库单表数据量过大的问题，垂直拆分按业务域拆库拆表，水平拆分按分片键取模或区间路由到多张表。分片后引入跨节点查询、分布式事务和全局 ID 生成等新问题。

## 主从复制与读写分离

MySQL 主从复制基于 binlog，主库将变更写入二进制日志，从库通过 I/O 线程拉取写入中继日志，再由 SQL 线程回放，默认异步复制存在主从延迟。读写分离把查询压到从库，需接受一定延迟并处理主从切换。
