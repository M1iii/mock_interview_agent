# Redis 面试知识

## 缓存穿透

缓存穿透指查询不存在的数据导致请求直接打到数据库，可通过布隆过滤器拦截不存在 Key 和缓存空值（短 TTL）两种方案解决。布隆过滤器有误判率，空值缓存需防止恶意 Key 打满内存。

## 缓存击穿

缓存击穿指某个热点 Key 在过期瞬间被大量并发请求同时访问，请求全部穿透缓存打到数据库，可通过互斥锁、逻辑过期和热点数据永不过期三种方案解决。互斥锁保证同一时刻只有一个请求重建缓存。

## 缓存雪崩

缓存雪崩指大量缓存 Key 在同一时段集中过期或 Redis 宕机，导致海量请求直接压垮数据库，可通过过期时间加随机值、多级缓存和限流降级等措施预防。宕机场景还需配合集群高可用与本地缓存兜底。

## RDB 持久化

RDB 是 Redis 按时间点将内存数据生成二进制快照文件 dump.rdb 的持久化方式，通过 save 或 bgsave 触发，bgsave 由 fork 子进程完成写入。RDB 恢复速度快但存在两次快照之间数据丢失的风险。

## AOF 持久化

AOF 持久化以日志形式记录每条写命令，重启时重放命令恢复数据，追加策略可选 always、everysec 和 no 三种，默认 everysec。AOF 数据安全性更高但文件体积大，可通过 rewrite 重写压缩。

## 过期删除策略

Redis 对过期 Key 采用惰性删除与定期删除相结合的策略，惰性删除在访问时检查是否过期，定期删除每秒抽取部分过期 Key 删除。两者结合避免单靠惰性删除造成过期 Key 长期驻留内存。

## 内存淘汰策略

Redis 内存达到 maxmemory 上限后按淘汰策略清理 Key，常见策略包括 noeviction、allkeys-lru、allkeys-lfu、volatile-lru、volatile-ttl 等。生产环境常用 allkeys-lru 或 allkeys-lfu 保证整体命中率。

## 分布式锁

Redis 分布式锁基于 SETNX 加过期时间原子命令实现，解锁需先校验 value 再删除防止误删他人锁，可使用 Redisson 看门狗续期机制解决锁过期而业务未完成的问题。Redlock 算法在集群多主节点上加锁以提升安全性。

## 主从复制

Redis 主从复制通过全量同步加增量同步实现，从节点初次连接发送 psync 触发 RDB 快照全量同步，后续通过复制积压缓冲区的命令流增量同步。主从实现读写分离与数据冗余备份。

## Redis 集群分片

Redis 集群通过槽位分片将 16384 个哈希槽分布到多个主节点，Key 经 CRC16 计算后对 16384 取模定位所属节点。集群支持横向扩容、自动故障转移，客户端需处理 MOVED 重定向。
